# 数据存储与备份策略

> 回答三个问题：你的数据存在哪、怎么不丢、怎么带走。对应 README「数据只存本地」承诺的完整说明。

## 一、数据存在哪

| 数据 | 形式 | 位置 |
|---|---|---|
| 饮食（含营养素明细）/ 运动 / 待办记录 | Room 数据库（SQLite 文件 `daily_control.db`） | 应用私有目录，仅本应用可读 |
| 设置（主题、提醒时刻、唤醒计划、备份状态等） | DataStore 配置文件 | 同上 |

应用私有目录受安卓沙箱保护：其他应用、文件管理器、USB 连接的电脑都读不到。**没有账号、没有云端、没有任何网络上传**——唯一的网络出口是你在设置里自己填的 AI 接口（第四阶段启用），且只发送你主动触发的汇总数据。

## 二、怎么不丢：备份机制（v0.3.1 起）

### 自动备份（安全网）

- **每周**自动把全部数据写成一份 JSON 文件，存入系统**「下载」目录**
- 下载目录属于共享存储：**卸载应用、清应用数据都不会删掉这些备份**
- 滚动保留最近 **4** 份，更旧的自动清理
- 排程同样具备开机/启动自愈（重启不丢备份计划）
- 排程设计注意：备份计划时刻存档在 DataStore，应用启动按存档幂等重排——避免「每次启动一律 +7 天」导致天天开应用的用户备份被无限推后

### 手动导出（随身带走）

设置 → 备份与恢复 → **导出全部数据**：经系统文件选择器存到你指定的任意位置（本地、网盘、发给自己都行）。

### 备份文件格式

单个 `.json` 纯文本文件，结构：

```json
{
  "formatVersion": 1,
  "exportedAt": 1760760000000,
  "appVersion": "0.3.1",
  "data": { "dietRecords": [...], "nutrientItems": [...], "exerciseRecords": [...], "todoTasks": [...] },
  "settings": { "theme_mode": "system", "...": "..." }
}
```

- **记事本可直接打开**：亲眼确认里面存了什么、没有任何多余信息，这是「本地存储」承诺的可自查佐证
- 带格式版本号：将来数据结构演进时旧备份仍可识别处理
- 恢复写入保留记录原 id：营养素明细的归属关系、待办与提醒的映射都完整还原

## 三、怎么恢复

设置 → 备份与恢复 → **从备份恢复**：应用直接列出**下载目录里自己的全部备份**（自动备份、恢复前快照、手动导出到 Download 的文件），每行带内容摘要（N 饮食 · N 运动 · N 待办），点选即可，不需要翻系统目录：

1. 点选一份 → 解析校验并**预览**，坏文件在列表里直接标「无法读取」、不可选
2. 确认后自动先把**当前数据**另存一份「恢复前快照」到下载目录——恢复错了可退回
3. 整体替换数据库与设置，随后自动重排全部提醒

备份存在其他位置（网盘、别的目录）时，用清单底部的「从其他位置选择文件…」走系统文件选择器。

## 四、典型场景操作路径

| 场景 | 步骤 |
|---|---|
| 换手机 | 旧机导出一份（或直接用每周自动备份）→ 新机装应用 → 从备份恢复 |
| 误删应用 | 下载目录里最近的周备份还在 → 重装 → 恢复 |
| 升级安装包（签名不变） | 直接装，数据不动 |
| 未来从 debug 版换正式签名版 | 先手动导出 → 卸载 → 装正式版 → 恢复 |

## 五、实现速览

代码在 `backup/BackupManager.kt`（独立协调层，讲解见 [code/util-and-entry.md](code/util-and-entry.md)）；导出/恢复为数据库事务级整体操作；自动备份经 `MediaStore.Downloads` 写入，无需存储权限。
