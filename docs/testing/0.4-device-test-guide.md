# 0.4.0 AI 生活建议 · 真机实测手册

> 在你自己的手机（红米 HyperOS）上验收 AI 功能。全程用自己的 AI 账号 Key，
> Key 只会保存在手机本机，不会出现在任何备份或代码里。
> 前置：已按首启向导完成权限设置（通知、精确闹钟、自启动、电池无限制、渠道三件套）。
> 新渠道提醒：**系统设置 → 通知 → 每日掌控** 里会多一个「AI 报告」渠道，若锁屏想看到凌晨的通知，记得把它的「三件套」也打开（默认等级为无声，不会半夜响铃）。
>
> **0.4.1 追问机制验收（2026-10-25 追加）**：装 0.4.1 后，看当天报告详情是否出现「AI 的追问」板块（AI 认为信息足够时可能不问——连看几天）；有问题就顺手作答，次日报告详情展开「本次发送的数据」，核验「用户对此前追问的补充」段确实带上了你的回答、档案型问题（如身高体重）答过一次后进入 AI 页「档案」入口且 AI 不再重复问；「历史」入口可回看全部回答。全程应无任何催促通知。

## 一、配置接口（约 2 分钟）

1. 打开应用 → 底栏 **设置** → **AI 接口** 区
2. 填三项（以 DeepSeek 为例）：
	- 接口地址：`https://api.deepseek.com/v1`（智谱 GLM 为 `https://open.bigmodel.cn/api/paas/v4`；其他服务商抄控制台给的 Base URL，一般以 `/v1` 结尾）
	- API Key：你在该服务商控制台创建的 Key（粘贴时默认掩码显示，可点「显示」核对）
	- 模型名：如 `deepseek-chat`（智谱如 `glm-4-air`）
3. 点 **测试连接** → 预期：绿色「连接成功，配置可用 ✓」（几秒内）
	- 若红字「HTTP 401，Key 无效」→ Key 抄错了或没复制全
	- 若「HTTP 404，接口地址不存在」→ 地址少了或多了路径，对照服务商文档
	- 若「网络不通」→ 手机断网或该地址被网络环境屏蔽

## 二、生成第一份报告（约 1 分钟等待）

前提：昨天或近几天有过饮食/运动记录（记录越多报告越有料；一点记录都没有时报告会明显空泛，属预期）。

1. 底栏 **AI** → 看到「还没有生成过报告」状态卡与「立即生成昨日报告」按钮
2. 点 **立即生成昨日报告** → 按钮出现小转圈与「生成中…」提示（大模型需要几十秒，期间可切出应用）
3. 预期结果：
	- 提示「已生成 X月X日 的报告」，列表出现一条带 **首份** 徽标的报告
	- 点开报告：总评一行、饮食分析卡、运动分析卡、3~5 条建议（每条带主题词与级别）
	- 内容应与你的真实记录相关（提到你吃过的食物/做过的运动），而不是泛泛而谈

## 三、隐私自查（重要）

在报告详情页滚到底部，有两个折叠项，点开逐一检查：

1. **本次发送的数据（隐私自查）**：亲眼核对——只有日期、餐别、时间、食物、饭量、成分、运动类型等中文键数据，加上一份「近 30 天概要」统计；**没有 API Key、没有待办内容、没有背单词记录**
2. **原始返回（AI 回复原文）**：AI 实际回复的全文，与应用拆解出的板块一致

再做一个备份核验：设置 → 备份与恢复 → 导出全部数据 → 用文件管理器/记事本打开导出的 JSON → 全文搜索你的 Key 片段 → **应搜不到**。

## 四、失败与自动补交（模拟中断）

1. 设置 → AI 接口 → 把 **模型名** 随便改成一个错值（如 `wrong-model-x`）→ 保存
2. AI 页 → 立即生成 → 预期：红字提示失败原因（如 HTTP 404 或 400，含服务商返回的说明）；状态卡同屏显示该错误；**昨天的旧报告不受影响**
3. 把模型名改回正确值 → 再点立即生成 → 预期：恢复正常出报告
4. （可选）验证「中断几天自动补交」：设置 → 调试工具 → 展开后点 **AI调试：水位线回拨3天** → 回 AI 页点立即生成 → 预期：生成一份带 **回顾** 徽标的报告（对中断时段做整体回顾分析）

## 五、凌晨自动报告（次日早晨验收）

今晚睡前确认：手机不断电、应用处于已配置状态（无需挂在后台，闹钟会唤醒）。

次日早晨预期：

1. 通知栏有一条「今日 AI 报告已生成」（无声送达，不会吵醒你），点开直达 AI 页
2. 报告列表多出昨日日期的报告；状态卡「上次报告」更新为昨天
3. 若凌晨恰好断网/欠费：通知会变成「AI 报告生成失败」+ 原因，且网络恢复后打开应用会自动补生成（启动自愈）

## 六、快速验证凌晨链路（不想等到明早）

设置 → 调试工具 → **AI调试：报告闹钟调到1分钟后** → 锁屏等待约 1~2 分钟 → 预期收到报告通知（与凌晨 4:00 走完全相同的链路）。注意：若昨天报告已生成，此次触发会因「已是最新」而静默——先做第四节第 4 步的「回拨水位线」再造缺口。

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 生成失败：HTTP 402，账户余额不足 | 服务商账户欠费，充值后次日自动补交，无需手动处理 |
| 生成失败：连接超时 | 凌晨网络不稳或服务商限流；会自动补交 |
| 报告「格式异常·原文」 | 模型偶发没按约定格式回复，原文已保存可阅读；回列表再点一次「立即生成」即可重试 |
| 报告内容很空泛 | 近期记录太少（概要是 0/30 天）——多记几天再看 |
| 想换一家服务商 | 改设置里的地址/Key/模型名即可，历史报告保留；首份基线报告会按新模式重新建立 |
