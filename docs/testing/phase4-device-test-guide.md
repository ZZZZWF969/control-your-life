# 第四阶段·真机测试手册（红米 HyperOS 有线连接）

> 面向项目所有者的操作手册：每一步写清「在哪点、看到什么算成功」。
> 全程约 40~60 分钟（含两次等待闹钟的自然时间）。
> 任何一步卡住或结果不符，直接停下来拍照发我，附带「第几步」即可，不用自己排查。

## 一、测试目标

在真实 HyperOS 环境验证六件事（模拟器验证不了的）：

1. 三餐询问在真机准点触发
2. 背单词循环提醒与「今日已背」停止
3. 测试待办 3 分钟准点触发
4. 起床唤醒双保险：引导跳转时钟手动开闹钟 + 应用渐进震动末声保底（模拟器做不到的核心项）
5. 手机重启后提醒自动恢复
6. 划后台/锁屏后提醒仍可靠

## 二、准备工作（你操作，约 10 分钟）

### 1. 打开开发者选项（若已开过可跳过）

- 设置 → 我的设备 → 全部参数与信息 → 连续点「OS 版本」7 次
- 提示「您已处于开发者模式」即成功

### 2. 打开 USB 调试

- 设置 → 更多设置 → 开发者选项 → 找到「USB 调试」→ 打开（弹窗选允许）
- 数据线连电脑（传文件模式）
- 手机弹出「允许 USB 调试吗？」→ 勾选「一律允许使用这台计算机」→ 允许

### 3. 安装应用（我来）

连好后告诉我，我在电脑上执行安装和检查。若你想自己装：手机上任意方式接收 `app-debug.apk` 安装即可，但**保留 USB 连接**——测试中我需要用电脑看日志。

### 4. 权限四连（关键！少一个提醒就不可靠）

安装完成、首次打开应用后，逐项设置（HyperOS 菜单名以你的系统版本实际显示为准，大致路径如下）：

| # | 权限 | 路径 | 目标状态 |
|---|---|---|---|
| 1 | 通知权限 | 打开应用时弹的系统授权 → 允许；或 设置→应用设置→应用管理→每日掌控→通知管理 | 全部允许 |
| 2 | 锁屏通知 | 设置→通知与控制中心→锁屏通知 | 「显示锁屏通知」开启 |
| 3 | 自启动 | 手机管家→应用管理→权限→自启动管理→每日掌控 | 开启 |
| 4 | 电池无限制 | 设置→省电与电池→应用智能省电→每日掌控 | 选「无限制」 |

还有一项「精确闹钟」到时由应用引导：打开应用→设置页，若顶部出现红色「精确闹钟权限未授予」提示，点「去授权」→ 系统页里把「闹钟和提醒」设为允许。

### 5. 记录不背单词包名（我来）

手机装好「不背单词」后我用 adb 读取真实包名，替你填进应用设置页。

## 三、六项实测（每项都有「预期」，不符就拍照）

### 测试 1：测试待办准点触发（约 5 分钟）

1. 应用 → 设置 → 「创建三分钟后的测试待办」
2. 按主屏键把应用退到后台，**锁屏**放着等
3. 预期：约 2 分钟后锁屏上出现「测试待办 将于 XX:XX 开始」通知
4. 解锁点通知 → 直接落在提醒页，今日待办列表里有这条
5. 在列表里把它勾选完成（或删除）

### 测试 2：背单词循环与确认（随测试 1 后顺手做）

1. 应用 → 设置 → 「30 秒后模拟背单词提醒」→ 退后台锁屏
2. 预期：通知到达，点开通知 → 提醒页 → 状态卡点「今日已背」
3. 再点一次模拟按钮 → 30 秒后**不再**有通知（循环已停）

### 测试 3：三餐询问真实触发（等待自然时间，可与其他并行）

方案 A（等真实饭点）：把三餐时间设置成最近的整点，等它自然响。
方案 B（快验）：设置→「1 分钟后模拟早餐询问」→ 若当天已记录早餐则无通知（正常），改试午餐/晚餐对应时段。
- 预期：通知点击后直接弹出该餐的预填表单

### 测试 4：起床唤醒双保险 ★ 核心项（2026-10-17 方案改版）

> 前置：设置 → 通知与状态栏 → 通知管理 → 每日掌控 → 「起床闹铃（震动）」渠道的
> 「允许通知/悬浮通知/锁屏显示」三件套都打开（HyperOS 按渠道开关，见 env-pitfalls #16）。

1. 提醒页 → 「去规划今天 / 明天」→ 加一条任意任务 → 选「明天」→ 勾「早八」→ 保存
2. 预期：弹出「去时钟开一个闹钟」引导框（建议 08:00）→ 点「去时钟」→ 手机时钟应用**直接打开闹钟列表页**（应用不会替你新建闹钟）
3. 在时钟里手动开一个 08:00 的闹钟（或启用已有的）
4. 回到应用 → 提醒页应出现「明早有唤醒计划，去时钟开闹钟（建议 08:00）」入口按钮
5. 验证闹钟能响：在时钟里把闹钟临时改到 2 分钟后，锁屏等待——时钟铃声应正常响起（静音模式下也响）
6. 模拟应用末声：设置页 → 「30 秒后模拟末声（持续震动）」→ 锁屏等待
   - 预期：约 30 秒后收到「该起床啦·末声」通知，**持续间歇震动直到你点掉/划掉**，通知上带「检查时钟闹钟」按钮
   - 点「检查时钟闹钟」→ 应直接跳到时钟闹钟列表
7. 我这边同时用 adb 核对排程：4 条起床闹钟落在明早 07:30–08:00、末声恰为 08:00、时钟里不新增任何由应用创建的闹钟

### 测试 5：重启恢复

1. 正常重启手机
2. 重启后**先不要**打开应用（考验开机自启）
3. 等测试 1 里创建的下一条提醒时刻 / 或用电脑 adb 查排程状态（我来）
4. 预期：提醒照常触发（这条依赖「自启动」权限，若失败我们记录为 HyperOS 限制）

### 测试 6：划后台与锁屏可靠性

- 测试 1、2 已顺带覆盖（都是锁屏等待）；额外做一次：从最近任务里划掉应用 → 再点一次 3 分钟测试待办（需重开应用创建）→ 划掉 → 看是否仍触发
- 预期：仍触发（AlarmManager 不依赖进程存活）

## 五、出问题时

- 拍照/录屏 + 告诉我第几步
- 手机保持 USB 连接，我用电脑抓日志定位（你不用做任何技术操作）
- 已知风险点：HyperOS 各版本菜单路径略有差异、时钟应用对 SHOW_ALARMS 跳转的响应（若不响应会提示「未找到时钟应用…」并记录）、自启动被深度定制管控——都在预期内，逐个验证记录即可
