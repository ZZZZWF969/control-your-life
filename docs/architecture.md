# 工程架构说明（面向项目所有者）

> 目的：让你随时能看懂工程分了几层、代码怎么协作、改哪里会影响哪里。
> 概念都用大白话解释；本文随结构性变化同步更新（项目维护约定）。
> 更新时间：2026-10-23（0.4.0 第四阶段第一批：新增 ai/ 网络层——AI 接口配置、每日报告生成）

## 一、总览

单模块安卓应用（Kotlin + Jetpack Compose），代码全部在 `app/src/main/java/com/dailycontrol/app/` 下，按职责分五个包：

```
com.dailycontrol.app
├── DailyControlApp.kt   应用入口（进程启动时最先执行，注册通知渠道 + 启动自愈重排）
├── MainActivity.kt      唯一的界面容器（解析主题 → 挂载整个界面树）
├── data/                数据层：一切「存取」都在这
│   ├── entity/          表结构定义（饮食记录、运动记录、营养素行、待办、AI报告、餐别枚举）
│   ├── dao/             数据访问接口（增删改查的抽象声明，Room 自动实现）
│   ├── db/              数据库单例 + 版本迁移规则（当前 v5）
│   └── settings/        应用设置仓库（DataStore：主题模式、提醒时刻、AI 接口三要素等）
├── ui/                  界面层：一切「看得见」的都在这
│   ├── theme/           设计系统（颜色、形状——浅/深两套主题的定义处）
│   ├── components/      跨页面公共组件（时间选择弹窗、圆形徽标、确认弹窗、记一笔类型选择弹层）
│   ├── RecordSaver.kt   记录落库的公共事务（2026-10-19 新增）：今日页与记录页共用
│   └── screens/         五个页面（底栏四格 + 隐藏规划页）+ 各自的表单/卡片/今日页子组件
├── ai/                  AI 协调层（0.4.0 新增）：全应用唯一的网络出口都在这
│   ├── AiClient         OpenAI 兼容 HTTP 客户端（HttpURLConnection；错误码→可读原因映射）
│   ├── AiDataSummarizer 近 30 天统计概要（程序算好模式，AI 不必自己数流水）
│   ├── AiPromptBuilder  提示词组装（system 角色 + 按首份/日常/补交三模式拼数据）
│   ├── AiReportParser   返回正文宽容拆解（剥围栏/截大括号；拆不开则原文降级保存）
│   └── AiReportGenerator 生成编排器（单飞锁；「成功才记账」水位线；合并补交；14 天滚动清理）
├── notify/              通知层：渠道注册与发送（三餐/背单词/规划/待办/起床五个业务渠道 + AI 报告 + 通用）
├── backup/              备份协调层（2026-10-18 新增）：BackupManager——JSON 导出/恢复、
│                        每周自动备份到下载目录；它要同时指挥数据层与调度层，故独立成层
├── schedule/            调度层（第三阶段新增）：所有「定时」都在这
│   ├── ReminderScheduler  AlarmManager 精确排程封装（未授权精确闹钟时自动退化）
│   ├── ReminderReason     全部提醒类型的 requestCode 常量表（接收器按它分发）
│   ├── ReminderReceiver   到点接收器：按类型分发（询问/循环/规划/待办/起床/AI报告）
│   ├── BootReceiver       开机重排（依赖「自启动」权限）
│   ├── DailyPlanner       每日提醒排程（三餐/规划时刻）+ 待办自愈重排
│   ├── VocabPlanner       背单词锚点制循环（10:00 起每 90 分钟，完成即滚明天）
│   ├── AiReportPlanner    AI 报告排程（0.4.0）：三要素配置齐全时排每日 04:00，否则撤销
│   ├── WakePlanner        渐进唤醒排程（N 声撤旧排新、存档 DataStore、重启自愈）
│   └── SystemAlarmSetter  起床闹钟写入系统时钟应用（SET_ALARM 协议；双保险方案下停用，保留备用）
└── util/                工具层：无状态底层工具（时间换算/格式化 + 系统时钟跳转封装）
```

数据层第四阶段的变化：`ai_report` 报告表（DB v5）；DataStore 新增 AI 接口三要素与报告水位线等六个键（全部刻意不入备份——Key 属敏感信息，水位线属运行痕迹）。

## 二、分层与调用关系

原则：**上层调用下层，下层不知道上层存在**。箭头方向不可反转。

```
界面层 ui/
   │  读写数据 / 读设置
   ▼
数据层 data/  ──(Room 框架)──►  SQLite 文件（应用私有目录）
   ▲
   │  读设置（主题）
MainActivity（容器）

通知层 notify/ ←── 界面层调用（设置页的自检按钮）
                 ←── 调度层调用（ReminderReceiver 到点时发送各类通知）
                 ←── ai/ 层调用（报告生成结果的通知由调用方转发给 Notifier）

AI 协调层 ai/ ←── 调用 data/（明细与概要查询、报告落库、配置读取）
              ←── 调度层与界面层都只认 AiReportGenerator 这一个入口
              ──► 全应用唯一的网络出口：只连用户配置的那一个接口地址（INTERNET 权限仅此用途）

工具层 util/ ←── 谁需要谁调用（无状态、无副作用，最底层；ClockLinker 跳时钟被界面层与通知层共用）
```

一次典型调用的完整链路（以「保存一条饮食记录」为例）：

1. `RecordScreen`（记录页）打开 `DietEntrySheet`（录入表单）；
2. 用户点保存 → 表单把输入组装成 `DietRecord`（实体对象）回调给记录页；
3. 记录页在协程里调用 `db.withTransaction { dao.insert(...) }`（数据库事务）；
4. Room 把对象写进 SQLite，同时通知所有正在观察该数据的 Flow；
5. 记录页列表订阅着这个 Flow，数据库一变，界面自动刷新出新卡片——**界面不需要手动"刷新列表"**。

## 三、关键设计决策（为什么这样分）

| 决策 | 理由 |
|---|---|
| 数据库全局单例（`DailyControlDatabase.get()`） | 全应用共享一个连接，避免重复打开的开销与竞争 |
| DAO 只声明不实现（Room 编译期生成实现） | SQL 在编译期被检查，拼错列名直接构建失败而非运行崩溃 |
| 数据库版本迁移显式写在 `MIGRATION_x_y` | 升级不丢用户数据；schema 快照存档于 `app/schemas/` 可比对 |
| 记录与营养素明细同事务保存 | 要么全成功要么全不动，避免出现"有主记录没明细"的脏数据 |
| 餐别/营养素是独立实体类，界面卡片自己配颜色 | 数据层不掺界面概念，换 UI 不动数据库 |
| 时间统一存 epoch 毫秒，展示层才格式化 | 存储无时区歧义，显示随系统语言 |
| 主题与业务数据分离（DataStore vs Room） | 轻量配置与重数据各走各的通道，互不拖累 |
| AI 报告「成功才记账」水位线（`ai_last_report_epoch_day`） | 接口返回内容才推进；欠费/断网/超时一律不推进，缺口自动显形、次日合并补交——不为任何失败类别写专门逻辑 |
| API Key 只存 DataStore 私有目录、只出现在请求头 | 卸载即清除、不随备份导出、不进发送数据正文（报告页「本次发送的数据」可亲眼核验）——安全红线 |

## 四、界面层的页面构成

> 2026-10-19 页面整合批次：「提醒」页取消，职责并入今日页，底栏四格。

| 页面 | 文件 | 内容 |
|---|---|---|
| 今日 | `TodayScreen.kt` + `TodayVocabCard.kt` / `TodayTodoSection.kt` | 任务中枢：三餐完成度与运动小结、饮食/运动精简列表（行点击直接编辑）、背单词一句话卡、今日待办清单（已完成沉底）、去规划/去时钟入口、悬浮「记一笔」全程不跳页 |
| 记录 | `RecordScreen.kt` + `DietEntrySheet` / `DietRecordCard` / `ExerciseEntrySheet` / `ExerciseRecordCard` | 按日管理与增删改查 |
| 规划 | `PlanScreen.kt`（不在底栏，今日页入口/通知深链进入） | 为今天或明天安排待办与起床唤醒；保存后引导去时钟开闹钟（双保险） |
| AI | `AiScreen.kt` + `AiConfigSection.kt`（设置页内嵌） | 未配置时引导去设置；已配置时显示生成状态卡、立即生成按钮、14 天报告列表与详情（总评/饮食/运动/建议 + 原始返回与发送数据两个折叠自查入口） |
| 向导 | `OnboardingScreen.kt`（2026-10-19 批次四） | 首启权限引导：5 步分页，未完成时整屏替代主界面；完成/跳过后由 DataStore 标志控制不再出现 |
| 设置 | `SettingsScreen.kt` | 外观（主题三档）、提醒时间、跳转应用、备份恢复、重新查看引导、调试工具（折叠） |

（原「提醒」页 `RemindScreen.kt` 已删除：背单词卡迁为 `TodayVocabCard`，待办清单迁为 `TodayTodoSection` 并新增已完成沉底与反勾恢复闹钟，去时钟/去规划入口迁入今日页。）

底部导航在 `ui/AppRoot.kt`：它持有「当前在哪页」的状态，切换页面 = 交换界面树里的内容，各页面互不直接引用（今日页跳记录/规划页走的是导航路由，不是直接调用）。
